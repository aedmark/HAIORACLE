Phrase Normalization & Deterministic Seed Hashing

#
foundationsdeterminismsecurity

Transforms arbitrary human text input into an immutable unsigned 32-bit seed.

What it does

Accepts user text up to 72 characters, trims surrounding whitespace, collapses internal whitespace sequences into single ASCII spaces, converts text to lowercase, and hashes the normalized string into an unsigned 32-bit integer. Rejects empty phrases or whitespace-only inputs at the boundary.

How it works

The normalization and hashing pipeline follows a strict pure functional path in src/score.mjs:

  1. normalizePhrase() applies Unicode normalization, lowercasing, and regex space collapsing s.trim().toLowerCase().replace(/\s+/g, ' ').
  2. hashPhrase() executes a 32-bit FNV-1a non-cryptographic dispersion algorithm using offset basis 0x811c9dc5 and prime 0x01000193.
  3. Bitwise operations (Math.imul and >>> 0) guarantee that the resulting integer remains unsigned and bit-identical across JavaScript engines on all platforms.

Why it works this way

A creature's identity depends on exact determinism: confiding identical words must invariably summon the identical specimen. Using FNV-1a on normalized text avoids cross-browser string hashing discrepancies while forgiving accidental double spaces and letter case differences without altering semantics (ADR D-003).

LOLCODE 1.2 Interpreted Score Engine

#
interpreterlolcodegenerative

Executes the generative score spell inside a purpose-built in-browser LOLCODE interpreter.

What it does

Executes src/oracle.lol locally in JavaScript. The spell acts as the causal bandleader of the universe: it seeds every visual property, anatomical feature, musical mode, and accompaniment parameter across all six languages, emitting key=integer pairs.

How it works

The interpreter in src/lolcode.mjs implements an honest, spec-compliant subset of LOLCODE 1.2:

  1. Parses HAI 1.2 through KTHXBYE and manages a dynamic symbol table with lexical scoping.
  2. Executes variable declaration (I HAS A), assignment (R), math operations (SUM OF, DIFF OF, PRODUKT OF, QUOSHUNT OF, MOD OF), Boolean logic (BOTH OF, EITHER OF, NOT), condition blocks (O RLY? / YA RLY / NO WAI / OIC), switches (WTF? / OMG / OMGWTF), loops (IM IN YR / IM OUTTA YR), and printing (VISIBLE).
  3. Injects the normalized phrase seed as an initial global variable INPUT_SEED.
  4. Fails closed with exact line numbers and statement context whenever unsupported syntax or uninitialized variables are encountered.

Why it works this way

Rather than generating parameters through arbitrary JavaScript math, every creature's soul originates in LOLCODE. Purpose-building the interpreter avoids bundling heavy third-party runtimes, preserves the zero-dependency contract, and guarantees that errors are debuggable with precise line numbers (ADR D-002).

Zero-Dependency & Client-Only Privacy Boundary

#
privacyofflinezero-dependency

Maintains an unyielding guarantee that all computation, rendering, and synthesis occur locally on-device.

What it does

Executes entirely in modern evergreen web browsers using native HTML5, CSS3, Canvas 2D, and Web Audio APIs. Transmits zero telemetry, analytics, cookies, local storage entries, or network requests after initial static file fetch.

How it works

The zero-dependency discipline is enforced both architecturally and by automated CI tests:

  1. tests/static.test.mjs scans all authored source files, asserting that no http:// or https:// URLs, external CDN imports, or node_modules references exist.
  2. All six esoteric programs (src/oracle.lol, src/beat.mal, src/bass.bf, src/harmony.bfg, src/pad.piet, src/chimes.frac, src/chant.spl) are bundled as plain static text files served from the same HTTP origin.
  3. No server-side processing, database, or cloud infrastructure is involved.

Why it works this way

Privacy, speed, and durability are non-negotiable architectural pillars. Relying on remote servers or third-party CDNs introduces tracking risks, network latency, bit rot, and external failure points. A static zero-dependency toy remains functional indefinitely (ADR D-001).
